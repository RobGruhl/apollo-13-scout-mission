Reading the numbers

  • Verified visits ≈ how many kids. Only successful sessions from real browsers count — failed requests, secrets probes, headless browsers, and known bot user-agents are excluded by the query itself. Each QR scan at the table lands here.
  • The service worker hides repeat visits. After the first load, the whole site is cached on the phone, so a scout replaying the mission offline generates no new traffic. First visits are counted reliably; browsing depth is undercounted.
  • Unique devices is the raw number. Cloudflare computes it before filtering, so crawlers are in it. When the two disagree, trust verified visits.
  • How many scouts total = verified visits (every QR scan lands on the landing page). How many finished = the two /ping/…completion/* rows above, added. How many of each victory = the four /ping/card/* counts — those already combine the classic mission and the Apollo Trail, since a trail winner walks up to the table for the same card.
  • The pings are all 404s on purpose. The site is static, so there's nothing to receive them — Cloudflare counts the request path at the edge and the 404 costs the scout nothing. Every one of them is disclosed on /privacy.html; if you change a beacon, change that page in the same commit.
